# Project Directory Structure & Context Guide

This document outlines the organized folder structure of the **SW-BTED** (Software Requirement Tree Edit Distance) research repository. Reference this file to understand the architecture, data flow, and experimental setup.

---

## 2. Key Directories Context

### `src/` (Source Code)
Contains the implementation pipeline of the proposed SW-BTED algorithm. The processing sequence is:
1. `01_parser.py`: Reads the raw docx templates from `samples/`, structures them into 4 domains (Business Context, Functional, Technical Realization, Execution Planning), and resolves elided subjects by prepending actors.
2. `02_role_extractor.py`: Parses the functional statements into T5 semantic roles (Actor, Action, Object, Technology, Constraint) using dependency trees.
3. `03_normalizer.py`: Performs CSO lookups and TEM term replacements, then encodes root and node-level texts with SBERT (`all-MiniLM-L6-v2`) to produce `trees.json`.
4. `05_sw_bted.py`: Runs the tree distance engine using the APTED algorithm under the customized cost matrices.

### `experiments/` (Experiments Engine)
Contains the entry-point runners for testing:
* `run_4layer_ablation.py`: Executes a comprehensive 19-variant ablation study testing tree hierarchy (Group A), node cost balance $\beta$ (Group B), leaf normalization (Group C), and global-vs-tree weight $\alpha$ (Group D).
* `run_4layer_evaluation.py`: Runs cross-validation and baseline comparison against SimCSE, lexical overlaps, and flat-sentence models.

### `docs/` (Documentation)
Subdivided to keep the workspace clean:
* `research_notes/`: Houses conceptual designs, migration notes, and mathematical logs.
* `plots/`: Stores charts depicting state distributions and runtime complexity scaling.
* `reports/`: HTML output files generated by diagnostic/evaluation scripts for graphical performance review.
